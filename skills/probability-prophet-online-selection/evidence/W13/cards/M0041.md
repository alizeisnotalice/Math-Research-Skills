# M0041 — Exact solutions to linear programming problems

**Source.** David L. Applegate, William Cook, Sanjeeb Dash, and Daniel G. Espinoza, “Exact solutions to linear programming problems,” *Operations Research Letters* 35(6) (2007), 693–699, DOI 10.1016/j.orl.2006.12.010. Read the complete six-page author manuscript at physical PDF pp. 1–6; it is not the publisher’s typesetting.

## Exact method and guarantee

For rational input \(c\in\mathbb Q^n,\ b\in\mathbb Q^m,\ A\in\mathbb Q^{m\times n}\), Algorithm 1 solves 
\[
\min\{c^Tx:Ax\le b\}.
\]
It starts at the best native floating-point precision \(p\), converts the rational data to that precision, and runs simplex, reusing a prior basis \(B\) if one exists. It then tests the candidate in rational arithmetic. Only if those exact tests certify the relevant outcome (optimality, unboundedness, or infeasibility) does it return; otherwise it raises precision and repeats, carrying forward the last basis. The implementation uses 128 bits on the second pass, then approximately \(1.5p\) rounded to a multiple of 32 bits. Thus the exactness comes from the rational certificate check, not from treating the floating-point objective or residual as proof.

The paper’s preceding “all rational arithmetic” approach changes every QSopt floating type and operation to GMP rationals. Its 170-instance experiment reports that this simple baseline can be impractical: for `pilot4`, the rational run took 5547.03s versus 0.20s for double precision. The proposed adaptive-precision approach instead reports timing ratios across small/medium/large benchmark sets and exact TSP subtour and small MIP computations. Those are computational findings, not a worst-case runtime or polynomial-time guarantee. The paper does not prove that the precision loop terminates quickly on every rational LP.

## Proof / certificate mechanism

The correctness mechanism is a verified basis-and-certificate pipeline. A floating solve proposes a basis; the candidate basis is reevaluated with exact rational arithmetic and the exact primal/dual conditions are checked. A failed check triggers another precision round rather than acceptance of an approximate answer. For the tested problem classes, an exact optimality certificate is primal/dual feasibility plus equality of rational objective values; infeasible and unbounded outcomes likewise rely on exact tests. This is an implementation design description plus computational evidence, not a new abstract simplex theorem.

**Local arithmetic check.** `../reader_batches/L09_batch3/computations/batch3_math_checks.py` constructs the toy LP min (x) subject to (x\ge1/3) and checks exactly with `Fraction` that primal (x=1/3), dual (y=1), feasibility and objective equality (1/3=1/3) hold. This validates certificate arithmetic on one instance only; it does not reproduce QSopt ex.

## Conditions, limits, and use

- Exact input coefficients are rational; the returned certificate is exact in that model.
- Floating-point precision is a search aid; exact rational checking is the acceptance condition.
- No universal bound on number of precision rounds, bit complexity, or wall-clock time is established.
- Useful for turning a proposed LP solution into a checkable rational certificate. It supplies no prophet/OCRS/poset theorem and no guarantee that a numerical optimizer’s basis is always easy to certify.
