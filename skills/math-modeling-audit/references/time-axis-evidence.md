# 时间轴与采样间隔核验

用于用户质疑工作簿、表格或图中输出频率的情形。审计要区分求解器内部时间步长、保存的原始时间节点和交付采样间隔；它们可以不同。内部采用细步长并不证明交付采样违反要求。

## 先取实际证据

1. 确认用户要求的输出间隔、起止时刻、端点规则与模板版本，并定位正在查看的实际工作簿和工作表。必要时比对导出脚本读取的模板与交付文件所用模板。
2. 读取时间列的原始单元格值、公式或缓存值、表头与单位；连续整数可能只是行号。仅看文件名、总行数、显示格式或序号列，不能认定实际时间间隔。
3. 将已确认的时间值换算到统一单位，检查相邻差分、起止时刻、重复和缺失节点。记录实际发现的间隔及异常；如时间列缺失或含义不明，结论应是证据不足，而非直接承认某种步长缺陷。
4. 追溯时间生成、单位转换、采样或插值、模板填充的路径。区分求解步长问题、导出采样问题、仅标注错误和模板版本不匹配，给出支持判断的文件位置。

## 诊断、改动与验证分开

“查明存在间隔问题”不等于已获准改写数据。按会话中已有授权处理：只有审计授权时交付诊断和修复方案；已授权修复时可执行相应范围的更正，不重复索取同一授权。

修复方案应先确定需要重采样、重新导出、调整标注还是更换模板；仅改行号或表头不能使底层采样满足要求。获准后保留原始结果，记录时间映射及插值方式，并重新读取导出文件核对实际时间值、单位和差分。除非求解结果本身不满足任务，不能把导出间隔修改自动扩大为重跑模型。

状态按已发生的事实更新：用户提出间隔质疑或已定位导出代码时，仍可能尚未更正数据；生成新文件后也要待回读检查完成才记为已验证。中断和未验证状态应保留到下一次交接或监测报告中，不能改写成已经解决的经验。
