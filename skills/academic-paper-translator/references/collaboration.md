# 多 agent 翻译协作

长文需要拆分、独立复核或用户要求多个 subagent 时读取本文件。任务记录、JSON 数据合同和覆盖校验以 [records.md](records.md) 为准；不要另造一套状态或结果格式。

## 拆分与调度

- 默认使用 native subagent，并继承当前模型；没有明确模型要求时不指定模型覆盖。
- 按完整章节或语义块拆分；尽量将定义与首次使用、定理与证明、公式与解释放在同块。确需拆开时，把依赖原文加入上下文。
- 短文或拆分后协调成本更高的任务由主 agent 完成，不为了并行强制拆分。
- 并发数服从本次运行实际可用额度，计入主 agent 和其他运行任务。没有空闲额度时排队顺序执行，不把某个固定人数写成前置条件。
- 主 agent 统一派发与回收；subagent 不自行递归创建团队。翻译与复核可以分批复用可用名额。
- 每次派发明确输入范围、验收要求和唯一输出文件。告知 subagent：它并非独自在工作，不得撤销他人编辑或修改未分配的文件。
- 每个输出文件只有一个写入者。主 agent 独占共享清单、术语表、合并稿和最终文档；subagent 只写本次分配的独立结果文件。

## 上下文与输出边界

主 agent 先提取有序来源、分配稳定单元 ID，再派发翻译。每个任务包明确区分：

1. **待译范围**：允许输出的单元 ID 及其原文，顺序与来源一致。
2. **只读上下文**：论文题目、摘要、章节层级、前后相邻原文、依赖的定义／图表／公式、术语表与版本。
3. **交付要求**：所用数据合同、唯一输出位置、疑问报告方式和完成条件。

- 上下文里的单元不自动进入输出范围；禁止为了读起来连贯重复输出相邻块。
- 将所有完成任务所需的信息显式放入任务包，不依赖 subagent 已继承完整对话或能访问主 agent 的临时状态。
- ID 标识来源单元，不随中文句子拆合而重新编号。允许自然调整中文句式，但结果仍须可映射回对应原文。
- 需要补充上下文时向主 agent 请求具体依赖；不得自行扩大输出 ID 范围。

## 术语与共享状态

- 主 agent 是术语表的唯一写入者；先确定核心术语、符号含义和必要的领域区别，再发布带版本的只读快照。
- 同一英文词可能因语境采用不同译法，例如 field、normal、kernel。按含义及适用范围记录，不机械全局替换。
- subagent 沿用已发布术语，在自己的结果中提交候选术语、歧义和理由；不要直接改共享表。
- 主 agent 裁决冲突后更新版本，并定位已译块中受影响的内容进行修订。不能只让后续任务采用新译法。
- 最终接受结果前确认其术语版本是否仍适用；版本较旧本身不要求全部重译，只处理实际变化影响的单元。

## 回收、复核与整合

- 收到结果仅表示已产出。主 agent 按合同核对 ID 范围、重复／缺失、顺序、保留项和未解决疑问，通过后才记为已验收。
- 覆盖校验不能代替语义复核。结合 [translation-quality.md](translation-quality.md) 检查难句、否定、量词、条件、数字及公式引用。
- 可将高风险片段交给独立复核 subagent，提供对应原文、译文、上下文与术语版本；要求返回具体 ID、问题依据和建议修订。
- 复核者不直接修改翻译者的输出或共享稿。主 agent 核实建议、决定修订并留下可追溯的有效结果。
- 主 agent 按来源顺序合并，复查跨块衔接、术语一致性、图表／公式／章节引用，统一制作 Word 与 PDF。
- 不把所有块都返回成功当成交付完成；合并后的覆盖校验与文档检查仍须通过。

## 失败、重试与续译

- 保存可恢复的任务记录；具体字段、状态及文件约定遵循 [records.md](records.md)。不要只依赖聊天中的“已完成”表述。
- 失败或中断时先检查已落盘结果；保留已验收部分，只重做缺失、未验收或证据不足的范围。
- 每次重试使用独立的尝试结果，避免与旧任务共同写一个文件。主 agent 选定有效结果后再合并。
- 迟到结果必须与当前任务范围、来源版本和已接受结果核对；过期结果不得覆盖当前有效结果。
- 来源变化后重新核对受影响单元及其上下文依赖；原文已改变的译文不能直接沿用“已验收”状态。
- 续译先读取清单、有效结果和术语版本，恢复未完成范围；不要从头重复翻译，也不要把缺失文件仅凭状态记录视为完成。
- 重复失败时缩小任务块、补充必要上下文或重新派发；仍不能完成则明确保留缺口与原因，不用猜译填满覆盖记录。

## 可选 DeepSeek Flash 路由

- 用户明确指定 DeepSeek Flash 时，复用已安装的 `$use-v4-flash-worker` 技能，按其当前工具说明调用 `deepseek` MCP，选择 `model="flash"`。
- DeepSeek 路由不使用 native `spawn_agent`、历史 `v4_flash_worker` 或 Hook 路径冒充跨提供商调用；native subagent 仅承担其实际可用模型的任务。
- 连接或配置不确定时按该技能检查映射，确认 `flash` 对应 `deepseek-flash`。连通性检查成功不能代替真实任务结果。
- 优先使用只读委托返回译文或复核意见，由主 agent 写入分配的结果文件，保持共享状态的单写规则。
- MCP 无法看到宿主对话或本地上下文时，将所需原文、术语、范围和验收条件完整传入；不要只给无法访问的路径。
- 使用异步任务时保存任务标识，并在相应 MCP 生命周期结束前收取结果；仍按主 agent 的并发队列调度。
- 用户明确指定的路由不可用、返回模型不符或任务失败时，报告具体阻塞并保留可恢复进度；除非用户已允许替代模型，不静默切换。
- 主 agent 仍负责模型结果验收、术语裁决和最终整合；采用外部模型不会降低覆盖或质量标准。
