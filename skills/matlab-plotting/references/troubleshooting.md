# 故障与兼容

## macOS 沙箱 Qt / neon 报错

本机已观察：沙箱内启动 R2026a ARM64 报 `Incompatible processor ... neon`，退出码 137；同一可执行文件在获准的沙箱外运行可正常返回版本和 `maca64`。因此该报错不能直接判定 CPU 不兼容或 MATLAB 损坏。

先检查安装路径、`uname -m` 与可执行文件架构。若一致，在宿主允许的审批流程中请求运行同一命令；不要通过改写系统安全设置、删除库或伪造 CPU 特性来规避。权限申请被拒绝时记录限制，不宣称完成 MATLAB 验收。MCP 启动也可能受到其宿主权限限制。

## 路径中有单引号

本机 R2026a 的 shell 启动器对 `-sd` 的单引号转义不完整，会在启动前报 shell syntax error。执行器因此用 subprocess 的工作目录和 `-batch` 内的 `cd` 设置目录，不把用户路径传给 `-sd`；MATLAB 字符串中的单引号按两个单引号转义。中文、空格和单引号路径均需用真实 MATLAB 验证，不能只靠 mock 测试。

## 启动、许可证与超时

- 找不到 MATLAB：`run_matlab.py --detect`；显式 `--matlab` 传可执行文件，MCP `--matlab-root` 传安装根目录，两者不能混用。
- 首次启动慢：默认 300 秒包含启动与绘图；查看日志/状态再决定是否延长，不同时启动第二次任务。
- 许可证或登录失败：向用户报告实际错误，不把安装存在当作许可可用，不重试无限循环。
- CLI 超时：状态为 `timed_out`，退出 124，只停止本次进程组。检查不完整文件后再运行；脚本自行脱离进程组创建的外部进程不在执行器的清理保证内。
- 宿主取消：SIGTERM 会停止本次 MATLAB 进程组，写入 `interrupted` 并返回 143；执行期间发生日志写入等异常也会清理仍在运行的子进程。SIGKILL 无法被程序捕获，遇到强杀仍应核对残留进程。
- MCP 调用断开：MATLAB 可能仍在运行。检查已知 PID、日志、文件时间戳和验证标记；不要只凭文件存在认定本次成功。
- 同一脚本错误修复两次仍重复出现时，停止机械重跑，报告日志与未解决原因，重新定位根因。

## 图形错误

- 中文方块：检查 `listfonts`、标签解释器和导出图。改用已安装 CJK 字体；不能通过删掉中文标签伪装修复。
- 图例或文字丢失：导出整个 figure/布局，等待 `drawnow`；查看真实 PNG/PDF。
- `heatmap` 是独立图表，不能对它调用普通 axes 专用接口；通过其自身属性修改。
- 白底黑字显式设置，避免桌面深色主题进入论文图；不要修改 `groot` 全局默认值。
- SVG 经 `exportgraphics` 需要 R2025a+；旧版不支持时报告并交付已有 PNG/PDF，不能把其他格式改后缀。
- 本 helper 使用 `arguments` 和名称值语法，首版只在 R2026a 验收。MCP 官方最低支持版本不代表本技能已在该版本测试。
